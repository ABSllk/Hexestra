# Hexestra 用户手册

*[English](user-guide.md) · [简体中文](user-guide.zh-CN.md)*

> [!WARNING]
> Hexestra 仅用于经过明确授权的安全测试。开始前确认测试对象、时间窗口、允许的方法、数据处理规则和停止条件。

## 1. 快速开始

这一节帮助你完成第一次使用。安装和各项功能的完整说明在后续章节。

### 1.1 打开或创建项目

启动 Hexestra 后，从项目菜单选择：

- **打开项目文件夹（Open Project Folder）**：打开已有文件夹；
- **创建项目文件夹（Create Project Folder）**：新建并打开文件夹。

一个项目通常对应一个客户、一次授权或一个独立实验环境。不要把互不相关的目标放进同一项目。

### 1.2 连接智能体

打开 **设置 > 连接（Settings > Connection）**：

1. 选择本机环境（Native）或 Windows 的 Linux 子系统（WSL）。
2. 选择或自动检测 Claude Code 可执行文件。
3. 选择模型和配置来源。
4. 点击测试连接，成功后保存。

Claude Code 需要预先安装在所选环境中。连接失败时先在同一环境执行 `claude --version`。

Hexestra 连接的就是这份本地 Claude Code。你可以沿用平时使用 Claude Code 的习惯，不需要学习另一套智能体命令方式。

### 1.3 设置测试范围

打开左侧 **资产 > 范围（Assets > Scope）**：

1. 选择白名单或黑名单模式。
2. 在允许规则中填写可测试对象，每行一条。
3. 在排除规则中填写不得触碰的对象。
4. 保存并人工复核。

示例：

```text
允许：
app.example.test
api.example.test
192.0.2.0/24

排除：
status.example.test
192.0.2.53
```

范围是给操作员和智能体的语义提示，不会强制阻断命令或网络请求。

### 1.4 建立初始资产和任务

把已知的域名、网段或应用告诉智能体：

> 建立初始资产和任务计划。

登记后的资产出现在资产清单和网络图中。任务出现在左侧任务树中。

### 1.5 发送第一条工作请求

保持权限模式为 **询问（ASK）**，选择一个任务或资产，然后发送：

> 分析当前项目，继续下一步。

Hexestra 会自动提供项目、范围、选中对象和内置规则；询问模式会处理需要批准的操作。智能体的回答、工具调用和结果显示在右侧时间线中。

### 1.6 推荐的第一次完整流程

1. 创建项目并设置范围。
2. 登记初始资产。
3. 让智能体建立任务计划。
4. 在询问模式下执行第一个低风险任务。
5. 用浏览器、流量或命令会话核对结果。
6. 保存证据，再整理发现记录、漏洞和报告。

## 2. 认识 Hexestra

Hexestra 是一款基于本地 Claude Code 的人工与智能体协作渗透测试集成环境。操作员和智能体共用项目、浏览器、终端、HTTP 流量、资产图、任务、证据和报告。

智能体的使用方式与 Claude Code 一致。Hexestra 在其上补充项目上下文、共享操作面、权限控制和持久化记录。未来可能接入其他智能体后端，但当前版本只支持 Claude Code。

Hexestra 以项目组织一次测试：

```text
项目
├─ 范围：哪些对象应关注或排除
├─ 资产：域名、地址、服务、应用、端点、身份等测试对象
│  └─ 关系：资产之间的归属、暴露和连接关系
├─ 任务：准备完成的目标任务与执行步骤
├─ 运行环境：浏览器、流量、终端与命令会话
├─ 记录：证据、发现记录、漏洞与报告
└─ 对话：智能体对话及其分支
```

### 2.1 什么是项目

项目（Project）表示一次独立的测试工作空间，对应磁盘上的真实文件夹。项目保存资产、任务、对话、流量、记录、工作区布局和权限偏好。重新打开同一文件夹，可以恢复上次状态。

主要项目数据：

| 位置 | 用途 |
| --- | --- |
| `.hexestra/project.json` | 项目标识和基础信息 |
| `.hexestra/project-state.json` | 工作区和项目偏好 |
| `.hexestra/engagement.db` | 资产、流量、记录和对话等结构化数据 |
| `ptt.md` | ATT&CK 任务树 |
| `targets.md` | 面向主机的目标兼容视图 |

不要在 Hexestra 运行时手工改写数据库。项目可能包含敏感目标、流量和证据，应纳入安全备份和访问控制。

### 2.2 什么是范围

范围（Scope）描述哪些对象应被关注或排除，参与资产筛选、任务规划和智能体上下文构造。

- **白名单（Whitelist）**：以允许规则为主要关注范围；
- **黑名单（Blacklist）**：以排除规则为主要边界；
- **允许规则（Allow rules）**：每行一个允许对象；
- **排除规则（Exclude rules）**：每行一个排除对象。

范围不是强制执行器。真正的控制来自权限模式、批准卡片、限制规则、网络配置和操作员判断。范围不能代替书面授权。

### 2.3 什么是资产

资产（Asset）是项目中可识别、关联和追踪的测试对象。它不只表示 IP 或主机，还包括：

- 域名、网段；
- 端口、服务；
- Web 应用、应用程序接口、端点、参数；
- 证书、身份。

资产可以保存类型、地址、状态、来源和关联记录。终端或扫描输出中的字符串只是候选发现；经过登记和回读确认后，才成为项目中的权威资产。

资产状态：

| 状态 | 含义 |
| --- | --- |
| `untested` | 尚未开始 |
| `in_progress` | 正在处理 |
| `scanned` | 已完成相关检查 |
| `vulnerable` | 存在已确认问题 |
| `compromised` | 已确认获得相应访问 |

### 2.4 资产图、目标视图与网络图

资产图（Asset Graph）是资产及其关系组成的权威模型。例如，域名可以解析到地址，Web 应用可以运行在服务上，端点可以属于应用程序接口。

目标视图（Targets）是从资产图生成的主机导向兼容视图，适合快速查看域名、地址和端口，但不能表达完整的应用、端点、证书和身份关系。

网络图（NetMap）是资产图的可视化入口，可从域名、网络或应用视角展示节点和关系。它不是另一份独立资产数据。

### 2.5 什么是任务

任务描述接下来要完成什么。Hexestra 按以下层级组织计划：

```text
ATT&CK 战术
└─ 技术
   └─ 目标任务（Objective）
      └─ 执行步骤（Execution Step）
```

目标任务记录目标资产、依赖、工具、成功条件和状态；执行步骤描述具体动作。聚焦任务会成为智能体的当前重点，任务追踪用于核对智能体、子智能体和工具活动。

任务表示计划和进度，不等于验证结果。把任务标记为完成不能替代证据。

### 2.6 什么是记录

| 记录 | 含义 |
| --- | --- |
| 证据（Evidence） | 可核验的原始材料，如流量、命令输出或文件内容 |
| 发现记录（Finding） | 基于证据形成的观察、线索、假设或行为记录 |
| 漏洞（Vulnerability） | 已验证的安全问题，包含影响、严重度和修复建议 |
| 报告（Report） | 汇总交付内容并关联发现记录和漏洞 |

推荐关系是“证据 → 发现记录 → 漏洞 → 报告”。智能体通常不会把未经核对的扫描输出直接当成漏洞。

### 2.7 智能体

智能体（Agent）可读取当前项目、选中对象和显式上下文，协助规划、操作和整理记录。项目文件和数据库才是权威状态；界面和对话是操作入口或状态投影。

智能体可读取并**操控** Hexestra 中几乎一切功能，例如：

- Hexestra 的浏览器：识别并点击元素，读取页面中的凭据（Token、JWT 等）；
- Hexestra 的流量捕获：开关抓包，自动重放或拦截关键请求；
- Hexestra 的代理：自动配置代理链，并可开启出口（出于安全，智能体可以开启代理，但不能关闭；关闭由操作员手动执行）。

网页、文件、终端输出和流量都是不可信数据，不会因为加入智能体上下文就变成可信指令。

### 2.8 项目状态与对话分支

对话可以建立分支来保留不同推理路径，但文件、资产、任务、流量、命令会话、浏览器和记录属于整个项目。切换或回退对话分支，不会撤销已发生的命令、网络请求或项目修改。

## 3. 安装、启动与首次配置

### 3.1 环境要求

- Windows x64、Linux x64（以 Ubuntu 24.04 为基准）或 macOS；
- 在智能体使用的本机或 WSL 环境中安装 Claude Code；
- 从源码运行流量捕获时，需要 mitmproxy/mitmdump；发行版已内置；
- Burp Suite、JDK 17 和 Mihomo 均为可选项。

### 3.2 安装 Claude Code

```bash
npm install -g @anthropic-ai/claude-code
claude --version
```

使用 Anthropic 账号时：

```bash
claude auth login
claude auth status
```

使用兼容 Anthropic 接口的服务商时，在启动 Hexestra 的同一环境中配置地址、令牌和模型变量。不要把密钥写进项目或仓库。

### 3.3 从源码启动

```bash
npm ci
npm run electron:dev
```

### 3.4 配置智能体连接

打开 **设置 > 连接（Settings > Connection）**：

1. 选择本机或 WSL。
2. WSL 模式选择发行版；Windows 默认参考环境是 `Ubuntu-24.04`。
3. 本机模式可自动发现 Claude，也可手工选择路径。
4. 选择默认模型和 Claude 配置来源（user、project、local）。
5. 测试连接并保存。

处理请求时不能切换连接或模型。Hexestra 当前连接本地安装的 Claude Code；未来可能扩展其他智能体后端。

### 3.5 项目菜单

- **打开项目文件夹**：打开已有项目；
- **创建项目文件夹**：创建并打开项目；
- **在文件管理器中打开**：查看项目目录；
- 从最近项目中移除：只删除最近记录，不删除磁盘数据。

## 4. 工作区与导航

| 区域 | 主要内容 |
| --- | --- |
| 左侧栏 | 资产、任务、记录、文件、流量、命令会话 |
| 中央标签页 | 欢迎、终端、编辑器、浏览器、流量、重放、记录、报告、工作流、知识精炼、设置 |
| 右侧智能体 | 对话、上下文、批准、问题、子智能体和后台收件箱 |
| 底部网络图 | 资产图、关系、视角和当前选中对象 |

标签页、活动标签和编号会按项目恢复。关闭标签通常只关闭视图，不会自动删除底层数据或停止后台活动。

### 4.1 文件与编辑器

左侧 **文件（Files）** 浏览项目目录，选择文件后在中央编辑器打开。编辑器支持 UTF-8 文本读写，本地项目文件上限为 2 MiB。

- 保存后，其他项目功能和智能体会看到新内容；
- 二进制或超限文件应使用外部工具；
- 文件修改属于项目副作用，不随对话分支回退；
- 远程文件的保存规则见“远程文件管理”。

### 4.2 共享上下文

打开的终端、编辑器、浏览器、流量和报告标签可以形成智能体共享上下文预览。选中的受管记录、浏览器页面、流量和连接构建结果也可显式加入下一条消息。

## 5. 范围、资产与网络图

### 5.1 资产工作区

左侧 **资产（Assets）** 包含：

- **清单（Inventory）**：搜索资产，并按类型或状态筛选；
- **变更（Changes）**：查看资产变化；
- **范围（Scope）**：维护允许和排除规则。

对资产右键可以：

- 在网络图中查看；
- 在浏览器中打开；
- 复制地址；
- 复制 JSON；
- 让智能体重新扫描或核对。

### 5.2 登记发现

扫描和终端输出不会自动写入资产图。智能体在处理发现时，会登记确认的资产、用 `asset_get` 回读确认，再单独建立关系。对于机器可读的扫描输出（例如 `nmap -oX -` 或 `httpx -json`），可以用 `asset_import` 一次性批量导入。

### 5.3 使用网络图

底部网络图支持：

- 域名、网络、应用三种视角；
- 选择节点并同步当前资产；
- 拖动节点和调整布局；
- 聚焦资产；
- 查看不同投影下的邻接关系。

空项目中的 **预览拓扑（PREVIEW TOPOLOGY）** 是合成示例，不会写入项目。

## 6. 任务树如何组织和驱动工作

Hexestra 的任务树不是一张只供人查看的待办清单。它同时是项目计划、智能体当前上下文、执行前置条件和结果追踪骨架。限制规则、技能、工具目录与工作流都围绕任务树协作，因此用户通常只需给出简短指令，例如：

> 继续当前任务。

Hexestra 会根据当前聚焦的任务，自动补齐与本次工作有关的目标、资产、限制规则、技能、候选工具、依赖关系和已有记录。

### 6.1 任务树结构

任务树采用以下层级：

```text
ATT&CK 战术
└─ ATT&CK 技术
   └─ 目标任务
      ├─ 执行步骤 1
      ├─ 执行步骤 2
      └─ 执行步骤 3
```

- **战术**说明当前工作服务于哪个高层目标。
- **技术**说明采用哪一类可识别、可统计的测试方法。新建目标任务必须绑定且只绑定一个技术。
- **目标任务**定义要完成什么、针对哪些资产，以及怎样才算成功。
- **执行步骤**是可以实际执行和验收的最小工作单元。

任务状态包括：`pending`（待处理）、`in_progress`（进行中）、`completed`（已完成）、`blocked`（受阻）、`skipped`（已跳过）和 `failed`（失败）。

### 6.2 目标任务

一个目标任务可以记录：

- 所属战术和唯一的 ATT&CK 技术；
- 目标资产；
- 所需能力；
- 首选工具和首选技能；
- 前置任务；
- 一项或多项成功条件；
- 当前状态、诊断信息和更新时间。

这些字段不是单纯的标签。Hexestra 会用它们解析本次工作所需的限制规则、技能、工具和依赖项。目标任务至少需要一个成功条件；前置任务必须存在并已完成或跳过，而且依赖关系不能形成循环。否则，任务会显示阻塞原因，实际执行也不会开始。

范围和任务目标是两件不同的事：任务可以明确指定目标资产；如果没有指定，当前选中的资产可以作为上下文提示。资产未列入范围或被排除时，Hexestra 会给出提醒，但当前的范围机制本身是建议性的，不等同于强制隔离或网络沙箱。

### 6.3 执行步骤

聚焦目标任务只会加载上下文，不会立即开始测试。实际动作前，智能体需要把目标拆成 3–7 个简短、以结果为导向的执行步骤，并聚焦其中一个可运行步骤。

每个执行步骤记录：

- 顺序和状态；
- 自身的成功条件；
- 结果摘要；
- 受阻原因；
- 从父目标任务解析得到的战术、技术、资产、能力、工具、技能和依赖上下文。

第一个真实工具动作发生时，当前步骤和父目标任务会自动进入“进行中”。步骤完成时应写入简洁的结果摘要；受阻或失败时应记录原因。已经开始的步骤不能再改名、调整顺序或删除；已有活动记录的步骤也不能删除。已有执行活动的目标任务不能随意改到另一项战术或技术下。这些限制用于保证计划、实际执行和审计记录保持一致。

### 6.4 聚焦任务与动态上下文

在任务详情中选择 **聚焦给智能体（Focus for Agent）**，即可告诉当前智能体分支接下来要处理哪个目标任务或执行步骤。

任务树由整个项目共享，但聚焦状态属于当前对话分支。因此，不同分支可以同时查看同一棵任务树，并分别聚焦不同工作；切换分支时，也会恢复该分支自己的任务焦点。正在被任何活动分支聚焦的任务不能删除。

每次普通对话时，Hexestra 都会根据当前焦点生成应用管理的动态上下文，其中包括：

- 项目、行动安全、自主模式和范围摘要；
- 当前目标任务与活动步骤；
- 固定版本的 ATT&CK 战术和技术；
- 目标资产及范围提醒；
- 当前有效的限制规则；
- 匹配到的技能与候选工具；
- 前置任务、阻塞原因和其他提醒；
- 相关证据、发现项和漏洞记录的标识。

为了避免一次性塞入过多内容，关联记录通常只注入标识和摘要。智能体需要细节时会通过工具按需读取。**这也是简短指令能够工作的原因：用户不必在提示词里重复项目背景和操作规范。**

### 6.5 限制规则

限制规则分为全局规则和项目规则。启用的规则可以是：

- **通用规则**：对所有任务生效；
- **战术规则**：目标任务属于指定战术时生效；
- **技术规则**：目标任务绑定指定技术时生效。

聚焦任务后，Hexestra 会把匹配的全局规则与项目规则合并为“当前有效限制”。内容相同的规则会去重，同时保留来源与匹配原因；可能互相冲突的规则会显示关联信息。限制文件无效时，诊断信息会成为任务阻塞项。

限制规则是智能体必须遵循的项目约束，但它不能覆盖系统安全要求、交战规则或权限机制，更不能作为操作系统级或网络级沙箱。修改限制规则需要操作者明确确认。

### 6.6 技能（Skill）

Skill 提供“应该怎样做”的方法、步骤和专业说明。Hexestra 会先处理项目技能与全局技能的同名覆盖关系，再从可用且已启用的技能中按以下优先级匹配：

1. 目标任务明确指定的首选技能；
2. 声明支持当前 ATT&CK 技术的技能；
3. 声明具备任务所需能力的技能；
4. 声明支持当前战术的技能；
5. 其他可用技能。

同名项目技能优先于全局技能；即使该项目技能被禁用，它也会遮蔽同名的全局技能。这样项目可以固定自己的工作方式，而不会意外回退到另一份同名说明。

技能只提供知识与操作方法，不会授予权限，也不会改变实际执行通道。例如，技能可以说明如何验证访问控制，但真正发送请求仍取决于 智能体工具、任务执行条件、权限模式和限制规则。

### 6.7 工具目录、执行条件与权限

工具目录回答“智能体可以考虑哪些工具”。每个普通对话回合都会收到全部启用项的精简索引；有聚焦任务时，Hexestra 会展开以下候选项的完整提示：

- 目标任务明确指定的首选工具；
- 声明支持当前技术的工具；
- 声明具备任务所需能力的工具。

停用项不会进入索引或候选项。目录不保存运行状态，也不判断工具能否执行；真实能力由 Shell、MCP、Browser、Traffic 等 智能体工具决定。技能或目录匹配成功都不代表可以立即执行。

一个真实动作开始前，会依次经过以下判断：

```text
已聚焦目标任务
    ↓
已规划 3–7 个步骤
    ↓
已聚焦一个可运行步骤
    ↓
依赖项、成功条件和诊断均无阻塞
    ↓
限制规则与交战规则允许
    ↓
按“询问 / 自动 / 绕过”权限模式处理工具调用
    ↓
执行并写入任务追踪
```

任务管理、限制规则查询和工具目录查询可以在尚未满足执行条件时使用，因为智能体需要靠它们补全计划或修复上下文；会产生真实影响的操作则必须通过上述检查。

### 6.8 工作流

工作流是可复用的操作流程，不是目标任务上的自动匹配字段。它不会仅因为某个任务被聚焦就自动运行；用户需要从 **任务 > 工作流（Tasks > Workflows）** 中主动选择并运行。

运行工作流时，Hexestra 会读取已保存的确切版本，记录名称、版本和一致性指纹，并把工作流正文与本次补充说明作为一条普通的智能体请求。智能体随后会：

1. 检查现有任务树；
2. 复用或更新已有的匹配任务；
3. 只创建缺少的目标任务和执行步骤；
4. 在任务树一致后继续第一个可运行任务。

工作流负责提供可复用的流程结构，任务树负责承载本项目的实际状态。工作流正文属于用户编写的操作说明，不能覆盖系统指令、限制规则、交战规则或权限模式。运行记录中的版本和指纹可以帮助确认一次执行究竟使用了哪份流程。

工作流库支持：

- 搜索、新建、编辑、预览和保存；
- 复制、导入、导出；
- 删除并二次确认；
- 在预览页运行；
- 运行前添加仅对本次调用生效的补充说明。

导入遇到同标识冲突时，可以覆盖或取消。

### 6.9 总结

| 部分 | 回答的问题 | 如何参与任务执行 |
| --- | --- | --- |
| 目标任务 | 要完成什么，怎样算成功 | 提供战术、技术、资产、能力、依赖和成功条件 |
| 执行步骤 | 下一项可执行工作是什么 | 作为真实动作、结果和状态的最小绑定单位 |
| 范围 | 哪些资产优先或应被排除 | 提供建议和提醒，当前不作为强制隔离 |
| 限制规则 | 必须做什么、禁止做什么 | 按通用、战术和技术自动匹配，形成规范性约束 |
| 技能 | 这类工作应该怎样做 | 按首选项、技术、能力和战术自动排序并提供方法 |
| 工具目录 | 智能体可以考虑哪些工具 | 提供提示目录，并按首选项、技术和能力展开候选详情 |
| 权限模式 | 某次工具调用是否要确认 | 在真实动作发生前实施批准控制 |
| 工作流 | 一套流程如何重复使用 | 用户主动运行后，复用、更新或补全任务树 |
| 项目记录 | 执行得到了什么 | 保存证据、发现项、漏洞和报告，并与任务关联 |

### 6.10 一个完整示例

假设目标任务是“验证登录接口的访问控制”，它指定了登录接口资产、一个 ATT&CK 技术、`HTTP 重放`能力、首选技能和成功条件。项目中还有一条“禁止修改真实账户数据”的技术限制规则。

聚焦该目标任务后，Hexestra 会自动匹配限制规则和技能，列出具备 HTTP 重放能力的候选工具，并检查前置任务。智能体先建立 3–7 个步骤，再聚焦第一个步骤。此后用户只需说：

> 继续当前任务。

如果权限模式要求询问，真实请求发送前仍会出现确认；如果缺少可用工具或前置任务尚未完成，该步骤会被阻塞并说明原因。运行“登录接口验证流程”工作流时，智能体会先复用这项任务，而不是机械地再创建一份重复计划。

### 6.11 任务追踪与完成判定

任务追踪（Task Trace）展示与目标任务或执行步骤相关的智能体、子智能体、工具调用、分支、时间和状态变化。一次活动首次出现时会绑定到当时聚焦的任务；之后即使切换焦点，历史绑定也不会被重写。

任务详情支持：

- 查看和编辑尚未锁定的目标任务或执行步骤；
- 聚焦给智能体；
- 更新状态、结果摘要和受阻原因；
- 查看任务追踪；
- 查看整体进度、ATT&CK 覆盖情况与成功条件。

判断一项工作是否完成时，应同时查看步骤状态、结果摘要、成功条件和关联记录，而不只看智能体是否停止输出。

## 7. 智能体

### 7.1 对话

把右侧智能体当作项目内的 Claude Code 使用，直接说要做什么即可。例如：

- `分析这个请求。`
- `继续当前任务。`
- `整理这些发现。`
- `把结果保存为证据。`
- `根据现有记录更新报告。`

通常不需要重复说明当前项目、范围、选中对象、可用工具或记录流程；Hexestra 已通过项目上下文和内置提示提供这些信息。只有目标、边界或期望结果发生变化时，才补充说明。

右侧智能体面板支持：

- 选择或新建对话；
- 查看共享上下文；
- 输入普通消息或斜杠命令；
- 添加附件；
- 查看时间线、工具调用和结果；
- 处理批准请求与问题；
- 查看子智能体；
- 查看后台收件箱。

### 7.2 附件

支持文本、代码、PDF、本地文件路径，以及 PNG、JPEG、GIF、WebP 图片：

- 每条消息最多 8 个附件；
- 每个附件最大 10 MiB；
- 附件和暂存上下文不能与原生命令同时发送。

### 7.3 命令

| 命令 | 用途 |
| --- | --- |
| `/distill` | 从来源提炼并创建或更新限制规则、技能和工作流 |
| `/compact` | 压缩当前上下文 |
| `/context` | 查看上下文信息 |
| `/cost` | 查看消耗信息 |
| `/help` | 查看运行时帮助 |
| `/status` | 查看运行状态 |

界面也会显示 Claude Code 发现的命令和已启用技能命令。原生斜杠命令会原样交给 Claude Code，不会自动附加普通项目上下文和附件。

### 7.4 权限模式与自主级别

| 模式 | 行为 | 建议 |
| --- | --- | --- |
| **询问（ASK）** | 有风险的工具调用前询问 | 默认使用 |
| **自动（AUTO）** | 后台策略分类并审查操作 | 规则明确的日常流程 |
| **绕过权限（BYPASS）** | 关闭软件权限检查 | 仅限隔离、可恢复且完全理解风险的环境 |

切换模式时，正在执行的请求不变，新模式从下一次请求生效。低、中、高自主级别只是工作偏好，与权限模式不同，也不会扩大授权范围。

### 7.5 批准与提问

工具需要许可时，时间线显示批准卡片。核对工具、目标、参数和影响后允许或拒绝。

智能体需要业务判断时会显示问题卡片，可选择现有选项或填写自定义答案。拒绝动作时最好给出替代方向。

### 7.6 运行中输入、停止与队列

智能体工作时仍可发送消息。新消息先显示为排队；被 Claude Code 消费后，排队标记会消失。

- 多条输入可能被合并；
- 一条输入不保证对应一条回答；
- **停止（Stop）** 中断当前请求；
- 已被消费的输入无法撤回；
- 尚未消费的输入可能继续保留。

### 7.7 对话分支

编辑已完成的用户消息会从该位置建立分支，原分支保留。活动请求中不能编辑消息或切换分支。

分支只分离对话历史；文件、网络请求、浏览器、命令会话、流量、资产和记录不会回滚。

### 7.8 子智能体

子智能体卡片和详情显示：

- 子任务和类型；
- 进度、工具或等待状态；
- 实时或最终耗时；
- 工具调用数和令牌信息；
- 活动时间线和最终输出。

子智能体结果应先与项目证据核对，再登记为权威资产或记录。

### 7.9 定时唤起与收件箱

智能体可以创建一次性定时唤起：

> 三分钟后再检查这条命令。

限制：

- Hexestra 和 Claude Code 必须保持运行；
- 这是一次性会话提醒，不是周期任务或系统闹钟；
- 后续工作回到原项目和原分支；
- 应用退出、休眠或运行时崩溃后的恢复不作保证。

后台完成、失败、等待批准或等待回答时，会进入 **智能体收件箱（Agent Inbox）**。点击条目可回到对应项目和分支。

## 8. 浏览器

内置浏览器（Browser）需要先打开项目，支持：

- 后退、前进、刷新；
- 新建标签；
- 地址栏导航；
- 复制地址；
- **询问智能体（Ask Agent）**；
- 查看加载状态；
- 把弹窗或新窗口转为 Hexestra 浏览器标签。

只支持 HTTP(S)。浏览器会话按项目和标签管理；开启流量捕获或项目代理后，会使用相应网络路径。

页面、选中文本和链接可加入智能体上下文。网页内容始终是不可信数据。

## 9. 流量、拦截与重放

### 9.1 捕获流量

在左侧 **流量（Traffic）** 中启动或停止捕获。列表支持：

- 搜索；
- 按暂停、完成、失败等状态筛选；
- 按浏览器或重放来源筛选；
- 按主机筛选；
- 查看某条原始流量的相关重放；
- 加载更多；
- 清理可删除历史。

流量保存在项目数据库中，但响应体和历史有容量边界。重要结果应及时保存为证据。

### 9.2 流量菜单

右键一条流量记录可以：

- 打开详情；
- 在 Hexestra 重放器中打开；
- 复制网址、原始请求、原始响应或 cURL；
- 询问智能体；
- 保存为证据；
- 按主机筛选；
- 查看相关重放；
- 在 Burp MCP 提供工具时发送到 Burp 重放器或入侵器；
- 放行或丢弃已暂停消息；
- 删除本地流量记录。

删除流量不会删除 Burp 历史、已保存证据或重放尝试。若该流量拥有 Hexestra 重放会话，该会话会一并删除。

### 9.3 请求与响应断点

捕获启动后，可以开启：

- **请求断点（Request Break）**：发送前暂停；
- **响应断点（Response Break）**：返回浏览器前暂停。

暂停后可查看并编辑当前一侧的原始内容，然后选择：

- **放行（Forward）**；
- **丢弃（Drop）**。

关闭断点会释放对应的暂停消息。编辑内容会经过解析和版本校验；冲突时应重新读取最新记录。

### 9.4 Hexestra 重放器

重放器（Repeater）支持：

- 编辑原始请求并发送；
- 查看每次尝试；
- 在历史尝试间切换；
- 恢复源请求；
- 复制请求或响应；
- 清空重放会话；
- 比较状态码、响应字节差和耗时差。

当前不能编辑重放 WebSocket 流量。**取消等待（Cancel wait）** 只停止界面等待，不保证取消已经发出的网络请求；结果仍可能进入流量列表。

### 9.5 保存证据

在详情或右键菜单选择 **保存为证据（Save as Evidence）**，会创建受管证据并保留资产和流量关联。

## 10. Burp Suite 集成

Burp 集成包含两个独立能力：

1. **桥接镜像（Bridge）**：把 Hexestra 捕获完成的交换镜像到本机 Burp；
2. **Burp 模型上下文协议（MCP）**：发现工具后，把流量发送到 Burp 重放器或入侵器。

### 10.1 配置桥接器

1. 使用 JDK 17 构建并加载 `resources/burp-bridge/hexestra-burp-bridge.jar`。
2. 在 Burp 的 Hexestra Bridge 页面取得回环端口和配对令牌。
3. 打开 **设置 > Burp**，填写端口和令牌。
4. 保存并连接。

镜像结果出现在 Burp **目标 > 站点地图（Target > Site map）**，支持时也可进入 Organizer；不会出现在 **代理 > HTTP 历史（Proxy > HTTP history）**。

桥接器或 MCP 失败不会停止 Hexestra 自身的流量捕获。

## 11. 终端、命令会话与远程文件

### 11.1 本地终端

中央终端（Terminal）是基础本地伪终端，默认从项目根目录启动，支持复制、粘贴、全选和常见终端交互。

智能体使用同一终端时可能持有执行锁。操作员可以中断或接管。终端输出不会自动登记资产。

### 11.2 命令会话配置

左侧 **命令会话（Shells）** 管理可复用连接：

| 类型 | 用途 |
| --- | --- |
| 本地 | 本机命令环境 |
| WSL | 指定 Windows 的 Linux 子系统发行版 |
| SSH | SSH、私钥、跳板和 SFTP |
| Web 命令会话（WebShell） | 通过 HTTP(S) 请求执行受控命令 |

命令风格可选自动、POSIX、PowerShell、CMD。资产角色可设为目标或基础设施；基础设施/仅跳板配置不会提供给智能体执行目标命令。

会话状态包括连接中、等待主机密钥、验证中、隔离、就绪、智能体锁定、断开、失败和关闭。

### 11.3 SSH

SSH 配置支持：

- 主机、端口、用户名；
- 密码、私钥、键盘交互；
- 保存凭据；
- 跳板配置；
- 主机密钥指纹验证。

首次连接必须显式核对并接受主机密钥，Hexestra 不会自动信任。密钥变化时应先调查原因。

### 11.4 共享会话与人工接管

受管命令会话支持连接、附加、读取、写入、调整窗口、中断、接管和断开。

智能体执行命令时拥有独占租约，避免双方同时输入。操作员可选择 **接管（Take over）** 或中断。命令审计可以保存为证据。

### 11.5 反向 Shell

可以保存、启动和停止监听配置。监听器必须绑定明确的网络接口或地址，不能使用任意通配地址。

新连接先进入隔离状态：

- 核对来源后绑定到已有资产；
- 不属于授权目标时拒绝；
- 绑定后再进入共享会话。

载荷生成器/连接构建器支持回连地址、公网 IP 检测、模板和无编码/Base64，并可复制或交给智能体。模板包括 PowerShell TCP、Bash TCP、Python 3、Netcat、BusyBox Netcat 和 PHP CLI。

只在隔离实验室或明确允许回连的目标上使用。

### 11.6 WebShell

WebShell 会话配置支持：

- 通用模式或 AntSword v2 PHP；
- 自动、PHP、JSP、JSPX、ASPX 运行环境；
- GET/POST；
- 无请求体、表单、JSON、原始请求体；
- `{{command}}` 或 `{{command_base64}}` 占位符；
- 自定义请求头；
- 可选忽略无效 TLS；
- 全响应、分隔符之间或正则提取；
- 自动、UTF-8、GB18030 编码；
- 操作系统命令、PHP 求值或自动模式；
- AntSword 密码参数和 raw/base64/hex 编码。

保存前应使用健康检查验证状态和系统信息。

### 11.7 远程文件管理

就绪且支持 SFTP 的 SSH 会话可作为文件数据源。支持：

- 进入主目录、上级或指定绝对路径；
- 刷新；
- 新建文件或目录；
- 打开并编辑文本；
- 上传、下载和取消传输；
- 重命名；
- 删除文件或目录。

## 12. 项目级 Mihomo 代理

### 12.1 节点与链路

**设置 > 代理（Settings > Proxy）** 可配置用户提供的 Mihomo。支持协议：

`http`、`https`、`socks5`、`ss`、`vmess`、`vless`、`trojan`、`hysteria2`、`tuic`。

支持：

- 自动检测或选择运行程序；
- 启动和停止；
- 开启或关闭项目出口强制；
- 刷新出口 IP；
- 通过 URI、表单或 YAML 导入节点；
- 批量导入、测试、编辑和删除节点；
- 创建最多 8 跳的链路；
- 调整节点顺序和移除跳点；
- 保存、激活、测试或删除链路；
- 查看关闭、启动中、就绪、降级、阻断和错误状态；
- 查看 TCP/UDP 就绪状态、出口 IP 和延迟。

节点凭据加密保存在全局保险库，项目只保存链路标识。

### 12.2 代理范围

受控路径：

- 浏览器；
- 流量和重放；
- 最外层 SSH 或跳板连接；
- Web 命令会话请求。

本地和 WSL 终端会注入代理环境变量，但程序可以忽略它们并直接建立连接。

不受当前代理控制：

- Claude 接口流量；
- 远程命令产生的二次出站；
- 系统其他应用。

Hexestra 不启用 TUN，也不修改系统代理。启用出口强制后采用**失败关闭（fail-closed）**：运行程序缺失、链路无效或运行失败时，受控路径被阻断，不会回退直连。

## 13. 记录与报告

### 13.1 四种记录

| 类型 | 关键字段 |
| --- | --- |
| 证据 | 资产、工具、类型、内容、来源和关联 |
| 发现记录 | 类型、可信度、状态、说明和证据 |
| 漏洞 | 严重度、状态、影响、修复、CVE/CWE/CVSS |
| 报告 | 状态、摘要、Markdown 正文和关联记录 |

发现记录类型包括 observation、lead、hypothesis、behavior、access、note；可信度为 low、medium、high；状态为 active、used、archived。

漏洞严重度为 critical、high、medium、low、info；状态为 confirmed、remediation、resolved、accepted。报告状态为 draft 或 final。

### 13.2 浏览和编辑

左侧 **记录（Records）** 可切换证据、发现记录、漏洞和报告：

- 点击打开详情；
- 右键可打开详情、复制 JSON、导出 Markdown 或删除；
- 删除当前记录时会清理其他记录对它的链接，不会级联删除被引用记录；
- 证据原始内容只读；
- 发现记录、漏洞和报告的业务字段可编辑；
- 报告正文按 Markdown 渲染；
- 发现记录可以关联资产，也可以作为项目级记录。

### 13.3 从证据到报告

```text
原始输出或流量
       ↓
      证据
       ↓
    发现记录
       ↓ 验证
      漏洞
       ↓
      报告
```

报告进入最终状态前，应确保关键结论具有可靠的重现步骤和结果。

报告预览支持智能生成：

> 根据关联记录更新报告。

记录属于项目级状态，不随对话分支回滚。

## 14. 知识精炼与智能体上下文

### 14.1 知识精炼

**任务 > 知识精炼（Tasks > Refinery）** 可以把外部资料转为可复用规则和流程：

1. 导入文本、Markdown、代码、PDF、DOCX 或技能导出文件；
2. 预览规范化后的来源；
3. 点击精炼；
4. Hexestra 新建智能体对话并发送 `/distill source:<id>`；
5. 智能体读取现有限制规则、技能和工作流并更新；
6. 检查摘要和实际产物；
7. 不需要时删除来源。

旧项目可能显示运行、作业和候选项页面，可查看日志、重试/取消、编辑和接受/拒绝。这是旧版离线精炼记录的兼容入口；新资料应使用 `/distill`。

### 14.2 技能

**设置 > 技能（Settings > Skills）** 支持：

- 查看全局、项目和核心技能；
- 新建、编辑、启用、禁用和删除；
- 编辑 Markdown 内容；
- 维护 ATT&CK 战术、技术、能力和风险元数据；
- 查看只读核心技能。

全局技能适用于所有项目；项目同名技能覆盖全局；禁用的项目技能会抑制同名全局技能。技能不会自动授予工具权限。

### 14.3 限制规则

**设置 > 限制规则（Settings > Restrictions）** 支持：

- 全局和项目规则；
- 新建、编辑、启用、禁用和删除；
- 通用绑定或 ATT&CK 战术/技术绑定；
- 搜索和筛选；
- YAML 导入预览、应用和导出。

两层启用项会合并。无效 YAML 会阻止应用并显示诊断。限制规则进入智能体上下文，但不是网络隔离。

### 14.4 工具目录

**设置 > 工具目录（Settings > Tool Catalog）** 管理全局 `user/tools.yaml` 提示目录。可以搜索、新增、编辑、启用、停用和删除目录项，并维护说明、风险、通道、Capability、ATT&CK 映射、命令提示和使用提示。已保存项的稳定 ID 不可修改。

目录只告诉智能体可以考虑哪些工具，不代表工具已安装、可执行或已获准使用，也不会探测或执行工具。实际操作继续通过 Shell、MCP、Browser、Traffic 等智能体工具完成。停用项不会进入智能体上下文；删除项不会改写历史任务中的首选工具 ID。

### 14.5 模型上下文协议 (MCP)

**设置 > 模型上下文协议（Settings > MCP）** 可在 user、project、local 三个作用域管理服务器：

- 新建、编辑和删除 JSON 定义；
- 刷新连接状态；
- 查看连接、工具数量和错误。

定义可能包含环境变量、请求头和凭据。避免在截图、共享屏幕或仓库中暴露这些值。

## 16. 常见用法

### 16.1 新项目基线

1. 创建项目并记录授权摘要。
2. 配置允许和排除规则。
3. 以询问模式连接智能体。
4. 登记已知域名、网段和应用。
5. 让智能体建立 ATT&CK 任务树。
6. 逐个确认目标任务和成功条件。

### 16.2 浏览器配合流量分析

1. 从资产清单打开 Web 应用。
2. 启动流量捕获。
3. 完成授权的页面操作。
4. 按主机筛选流量。
5. 打开关键请求并询问智能体。
6. 保存重要流量为证据。

### 16.3 拦截并修改请求

1. 启动捕获和请求断点。
2. 在浏览器触发请求。
3. 打开暂停的流量。
4. 核对目标、Cookie、请求头和请求体。
5. 修改允许测试的字段。
6. 放行或丢弃。
7. 关闭断点，避免后续请求堆积。

### 16.4 用重放器比较差异

1. 从已完成流量打开重放器。
2. 保留源请求作为基线。
3. 每次只修改一个变量。
4. 比较状态码、字节差和耗时差。
5. 保存有价值的结果为证据。
6. 在发现记录中说明观察，不要直接夸大为漏洞。

### 16.5 通过 SSH 共用会话

1. 新建 SSH 配置。
2. 核对主机、账号和跳板。
3. 验证主机密钥指纹。
4. 连接到就绪状态。
5. 让智能体先说明命令和预期。
6. 智能体执行时不要同时输入；需要介入时接管。
7. 保存关键命令审计为证据。

### 16.6 整理一次发现

1. 从流量、命令会话或文件保存证据。
2. 建立发现记录并填写类型、可信度和说明。
3. 继续验证并关联新证据。
4. 可复现且影响明确后建立漏洞。
5. 填写严重度、影响、修复和标准标识。
6. 把已验证记录加入报告。

### 16.7 制作可复用工作流

1. 打开任务 > 工作流并新建。
2. 填写名称、版本、说明和标签。
3. 在正文写明目标、输入、步骤、停止条件和输出格式。
4. 保存并预览。
5. 添加本次补充说明。
6. 运行并检查智能体是否遵循流程。
7. 导出稳定版本。

### 16.8 从资料提炼规则

1. 导入个人文档，测试规范或内部方法。
2. 预览来源并排除不应暴露的秘密。
3. 执行精炼。
4. 检查更新的限制规则、技能和工作流。
5. 复核作用域和风险元数据。
6. 用低风险任务验证效果。

### 16.9 配置多跳出口

1. 检测 Mihomo 运行程序。
2. 导入并测试节点。
3. 创建不超过 8 跳的链路。
4. 测试整条链和出口 IP。
5. 激活链路并开启出口强制。
6. 用浏览器或重放器做无害连通性检查。
7. 出现阻断或错误时先修复，不会自动直连。

### 16.10 让智能体稍后复查

> 三分钟后再检查这个任务。

结果会回到原项目和分支，并通过智能体收件箱通知。
